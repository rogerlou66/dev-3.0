# OSC 8 hyperlink URIs are captured from the PTY stream, not the terminal

## Context

Agents (Claude Code among them) render markdown links as OSC 8 hyperlinks. Two independent breaks kept them dead in dev3: tmux forwards OSC 8 only to clients whose terminal declares the `hyperlinks` terminal-feature (our attach client's `xterm-256color` never did), and CLIs gate emission on `supports-hyperlinks` heuristics whose `TERM_PROGRAM` allowlists (`ghostty`, `iTerm.app`, `kitty`, …) never include tmux, so nothing emitted OSC 8 in the first place.

## Investigation

With the plumbing fixed, links still did not click. ghostty-web 0.4.0 assigns `hyperlink_id` to cells (its renderer draws the hover underline from that), but its wasm module exports no hyperlink accessor at all — `WasmTerminal.getHyperlinkUri()` is literally `return null`, so the built-in `OSC8LinkProvider` always produces zero links and `LinkDetector.getLinkAt` finds nothing to activate. 0.4.0 is the latest release; there is no upstream fix to upgrade to. The URI enters the wasm parser and never comes back out.

## Decision

Capture URIs before the bytes reach the terminal. `src/mainview/terminal-osc8-links.ts`: `createOsc8Tracker` is a small escape-sequence state machine fed every PTY chunk in `writeToTerminal` (TerminalView) — it pairs each OSC 8 start/end and remembers visible label → URI (LRU, whitespace-stripped keys since wide glyphs read back from cells with padding blanks; the map is dropped on RIS and CSI 3J). Terminal content is untrusted, so the mapping is fail-closed: a label ever seen with two different URIs is poisoned and resolves to nothing — a later hostile line re-using an earlier label kills that link rather than retargeting it. `createOsc8LinkProvider`, registered via `term.registerLinkProvider`, finds contiguous `hyperlink_id` cell ranges per row (stitching wrapped rows, bounded, gated on `isWrapped` where the buffer knows it — ghostty reports scrollback rows as never wrapped, so unknown allows stitching and a miss falls back to the row's own segment), resolves the label through the tracker — falling back to the label itself when it is already a URI — and activates with `window.open` on Ctrl/Cmd+click (the desktop `new-window-open` intercept routes that to `Utils.openExternal`). URIs are validated by `safeHttpUri`: http(s) only (`mailto:` is a dead click on desktop — the intercept forwards nothing else), parsed with `new URL`, control characters and whitespace rejected (browsers strip raw newlines while parsing, so a prefix check alone lets `https://ok.dev\n@evil.example` land on evil.example). Because label and destination are independent in the escape sequence, `src/mainview/terminal-osc8-hover.ts` shows the resolved URI in a tooltip on hover — ghostty-web 0.4.0 never calls `ILink.hover`, so this is its own mousemove overlay. Emission/forwarding fixes live in `src/bun/tmux/config.ts` (`terminal-features …:hyperlinks`, `set-environment -g FORCE_HYPERLINK 1`) and `AGENT_ENV_DEFAULTS` in `shared-pure.ts`, spread below project env in every launch-site assembly so Project Settings / `.dev3` env can turn it off.

## Risks

Label→URI mapping is heuristic: two on-screen links sharing a visible label but not a destination both go dead (fail-closed, see above) unless the label is itself a URI, and a label whose glyphs the cell readback mangles (astral codepoints become blanks) may miss the map. tmux re-emits OSC 8 on every redraw, which only refreshes the same mapping. Non-http(s) URIs are deliberately dropped. `FORCE_HYPERLINK` is honored by `supports-hyperlinks` above every TTY check and, being process environment, is inherited by the whole launched tree (tmux sets it globally, so hand-opened panes too) — piped and captured output can therefore carry OSC 8 escapes into logs; accepted, since the variable is overridable per project and per agent config. If a future ghostty-web implements `getHyperlinkUri`, the built-in provider will start answering first and this provider becomes redundant — delete it then.

## Alternatives considered

Upgrading ghostty-web (no release implements the accessor); reconstructing wasm hyperlink ids by counting OSC 8 starts in the stream (ids are page-managed and deduplicated inside ghostty core — unreconstructible); rewriting the stream to append the URI as visible text (changes displayed content); patching the wasm (not ours to fork for this).
